# 秋招网申辅助中心 · resumeself

> 秋招最耗人的不是填表，而是**信息散落在十几个地方**。
> 这个站把它们收进同一处，并让它们互相对账。

面向所有求职者的**个人求职进程管理中心**：岗位追踪、投递看板、截止提醒、
网申资料库、简历导出、面试复盘、Offer 对比，全部收在一个站里。

数据存在**你自己的账号**里，AI 能力用**你自己的 API Key**。

线上：<https://resumeself.vercel.app>

---

## 一、为什么做这个

2027 届秋招的真实情况是这样的：

| 信息 | 它通常在哪 | 后果 |
|---|---|---|
| 岗位截止日期 | 公众号推文、企业官网 | 错过，且是事后才发现 |
| 投递进度 | 备忘录、聊天记录 | 记不清哪些投了、哪些该催 |
| 笔面真题 | 手机截图 | 面试前一晚翻不到 |
| 网申材料 | 一堆文件夹 | 每次填表都要重新找、重新敲 |
| Offer 条件 | 微信聊天记录 | 无法横向对比 |

真正的问题不是「缺一个工具」，而是**这些信息之间没有任何连接**。
你改了一个投递状态，岗位卡还停在旧的；你标了一个截止日期，日历里没有。
人脑要维护十几处副本的一致性，这是做不到的。

所以这个站的核心不是某个板块，而是**对账**：

```
网申资料库 ──复制字段──▶ 企业网申表单

岗位库 ◀──── 自动对账 ────▶ 投递记录
   │                            │
   └────── 截止日 ────▶ 日历提醒 ┘
```

投递状态一变，岗位卡、截止提醒、日历事件同步更新；删掉投递记录，岗位状态自动回退。
**联动只有一个出口**（`store → lib/reconcile.ts`），所有入口都走它 ——
否则岗位卡会永远停在旧状态，这正是早期版本的真实毛病。

## 二、它能做什么

### 网申资料库
12 大板块（个人信息 / 教育 / 实习 / 项目 / 证书 / 获奖 / 家庭…），每个字段一键复制，
直接粘进企业网申表单。秋招投几十家，同一份资料不用敲第二遍。

### 岗位库 ↔ 投递记录 ↔ 日历提醒
三者全量对账。支持批量导入：手上有 Markdown / 表格整理的岗位清单，
选文件或拖进来即可解析入库，**同一份反复导入不会重复堆积**（按公司 + 岗位归一化去重）。

### 数据洞察
投递漏斗（投了多少 → 笔试多少 → 面试多少 → Offer 多少）、
渠道效力（哪个渠道真的回消息）、城市分布，以及导出快照。

### 面试复盘 / Offer 对比 / 材料清单 / 简历版本 / 人脉内推 / 备考题库
面试当场记下问了什么；多份 Offer 摆在一张表里比条件。

### 邮件中心（可选）
接一个跑在你自己电脑上的邮件桥，自动识别面试 / 笔试通知，回写投递状态。

### AI 助手
用你自己的 API Key，对话即可操作站内数据（「把某某集团标记为已投递」
「列出未来 3 天截止的岗位」），另有 JD 解析、简历匹配度、公司背景、AI 参考答案、邮件代写。

### 导出
整站 JSON 备份、岗位 Markdown / CSV、投递 CSV、ICS 日历（含 -7d / -3d / -1d 闹钟）。

### PWA
装到手机主屏，**断网也能打开**（外壳与全部板块 chunk 都进 Service Worker 缓存）。

### 皮肤市场
顶栏那个调色盘图标（或「设置 → 外观」）里可以整套换掉视觉语言，五套设计语言、六张卡：

| 皮肤 | 一句话 |
|---|---|
| 极光玻璃 · 夜 / 晨 | 原来的样子，深空液态玻璃的两档明暗（**两张卡**，各占一档） |
| 纸 · 手记 | 暖米纸、陶土橙、衬线标题 —— 纸质阅读感 |
| 宣纸 · 水墨 | 宣纸底、墨字、朱砂印 —— 中式线装书 |
| 石墨 · 极简 | 纯白底、细黑线、零装饰 —— 瑞士国际主义 |
| 豆绿 · 护眼 | WPS 护眼绿 `#CCE8CF` 打底、近黑正文、低饱和 —— 长时间盯着不刺眼 |

皮肤只换外观，数据与布局不受影响；选择跟着账号同步。

**没有单独的深 / 浅色开关**：「明暗」是皮肤的一部分，不单独拧。想换明暗就换一张卡
（极光玻璃的「夜」与「晨」并排摆着）。原先顶栏与设置里各有一个 ☀️/🌙 按钮，
只在极光下有效，对另外几款皮肤的用户就是噪音，已整体删除。

实现上是一个与 `data-theme` 正交的 `data-skin` 维度（见 `src/lib/skins.ts` 与
`src/styles/skins.css` 顶部注释），市场里的缩略图用**皮肤自己的变量**实时绘制，
所以预览与实际效果不可能不一致。

## 三、技术选型与取舍

Vite 5 + React 18 + TypeScript。**无自建后端**，只有三处外部依赖，且后两项可选：

| 能力 | 依赖 | 必需性 |
|---|---|---|
| 账号与数据 | Supabase（Auth + Postgres） | 必需（也可换成自建或纯本机） |
| 邮件中心 | 用户本机运行的邮件桥 | 可选，不配则该板块显示引导 |
| 网盘备份 | 用户自己的 WebDAV | 可选 |

### 为什么是「一份 JSON 文档」而不是七张表

整站状态序列化成**单份 JSON 文档**写进 `profiles.data`（`jsonb` + `UNIQUE(user_id)`），
一次 upsert 原子落盘。

早期原型把资料 / 投递 / 日历 / 岗位 / 题库 / 公司拆成 7 张表，每次保存
「先把该表全删、再全插回去」，必然出三类问题：

1. **请求非原子** —— 第 3 轮失败就停在「投递删了、岗位卡还在」的半同步态；
2. **空数组也能删** —— 加载失败导致内存为空时，下一轮保存把云端整表抹掉；
3. **无法回滚**。

改成单文档后，这三类问题一次性消失。

## 四、快速开始

```bash
git clone https://github.com/你的账号/resumeself.git
cd resumeself
npm install
cp .env.example .env.local     # 填入你自己的 Supabase URL 与 anon key
npm run dev
```

数据库准备（**必做**，否则登录后存不进数据）：

1. 在 [Supabase](https://supabase.com) 新建项目（免费版够用）。
2. SQL Editor 里执行 `supabase/migrations/001_init.sql` 与 **`003_touch_updated_at.sql`**。
   （`002_storage.sql` 是早期原型的简历上传桶，现在不需要跑。）
3. Authentication → Sign In / Providers → Email → **关掉 `Confirm email`**。
4. Authentication → URL Configuration：Site URL 填正式地址，Redirect URLs 加上
   `https://你的域名/**`、`http://localhost:5173/**`、`http://localhost:4173/**`。

> ⚠️ 漏配 Redirect URLs 的后果很隐蔽：验证邮件里的链接会把用户重定向到默认的
> `http://localhost:3000`，用户点进去是打不开的页面，而 Supabase 面板上**不会报错**。

### 部署

```bash
vercel --prod
```

记得在 Vercel 项目里配好同样的环境变量，**然后重新部署一次**
（环境变量不作用于已构建的产物）。

**完整复刻指南见 [SKILL.md](./SKILL.md)** —— 可以直接丢给 Claude Code / Cursor / DSH
一类 AI 工具，让它照着重搭一套，含换数据库与国内云两条升级路线。

## 五、隐私边界

这是**刻意**的设计，不是偷懒：

- **站点不代转用户的模型请求** —— AI 请求从浏览器直连用户自己填的服务商。
- **AI Key、邮件桥令牌、网盘凭据、本机简历目录只存在本机浏览器**，不进云端账号。
  代价是 AI Key **不跨设备同步**，换设备要重填 —— 这是有意的取舍，避免密钥进数据库。
- **邮件桥的邮箱授权码**只写在用户自己电脑的 `mail-bridge/bridge.config.json`（0600），
  既不经过本站服务器，也不进数据库。
- **源码与构建产物中不含任何真实个人数据**，种子数据为空，所有内容由用户自己填写。
- `.env.local`、`bridge.config.json`、`bridge.token` 全部在 `.gitignore` 里。

## 六、开发者须知

> 这一节都是**真实踩过的坑**。改代码前请先读完，每条纪律背后都对应一次线上事故。

### 三条纪律

1. **读失败 ≠ 云端为空。** `CloudBoot` 分三态：`undefined` = 本机模式不连云；
   `{ok:false}` = 读取失败，用本机缓存撑界面但**禁止回写**；
   `{ok:true, state:null}` = 云端确实没数据，才允许把本机缓存推上去。
   把「读取失败」当成「云端空的」，就会用本机过期数据覆盖掉云端。

   - **「重试连接」必须先读通云端再重载页面**，不能只把写入开关拨开。
     读失败那段时间本机可能已改过、云端也可能被别的设备更新过，直接开始写入
     就是拿本机过期状态覆盖云端。

2. **写失败必须冒泡。** 每次改动先写 `localStorage`（断网不丢），
   再 700ms 防抖 + 单飞推云端；推送失败要在界面上显示原因，**绝不静默** ——
   「以为存上了其实没存」是这类站最致命的体验问题。

3. **多设备与多标签页都不能静默覆盖。**
   - **跨设备**：PWA 可以挂在后台好几天，重新获得焦点时先问服务端「你那边什么时候写的」。
     比自己新且本机无未同步改动 → 提示「载入云端最新」；本机有未同步改动 →
     **只警告、不给载入入口**，否则等于丢掉用户刚敲的内容。
   - **同浏览器多标签页**：监听 `storage` 事件。本页空闲才接纳对方快照；
     正在编辑（有弹窗或光标在输入框）就**不动、只提醒一次** ——
     去接纳会把用户正在敲的内容冲掉，那是用一个小问题换一个大问题。
   - 接纳后要跳过那一次回写（`adoptedRawRef` 比对），否则两个标签页会互相触发
     `storage` 事件来回弹。

   > 比对用的 `profiles.updated_at` **必须由服务端接管**。`profiles` 表原本只有
   > `updated_at TIMESTAMPTZ DEFAULT NOW()`，而 `DEFAULT` 只在 INSERT 时生效；
   > 走 upsert 的 UPDATE 分支时**客户端传什么就存什么**（实测：传 `2000-01-01`
   > 就读回 `2000-01-01`）。于是「服务端时间」实际是写入设备的本机时钟：
   > 设备 B 时钟慢两小时 → 它后改的数据时间戳反而更早 → 设备 A 判定
   > 「云端不比我的新」→ **既不提醒也不拦截**，下次写入整片覆盖 B 的改动，全程无提示。
   > `003_touch_updated_at.sql` 的触发器把 `NEW.updated_at` 强制改成 `NOW()`，
   > 客户端传什么都作废 —— 所以它**不是可选项**。

### `/api/webdav` 的安全边界必须守住

它是全站唯一的服务端代码（无状态转发，不存任何数据）。改动后跑
`node scripts/qa-webdav-guard.mjs`（30 项断言）。三个要点：

- **SSRF 判定必须在 URL 规范化之后**。只比对字面量会被这些写法绕过：
  `http://2130706433/`（十进制整数）、`http://0x7f000001/`、`http://127.1/`、
  `http://[::1]/`（注意 `new URL().hostname` **保留方括号**，`h === '::1'` 会漏），
  以及无点号的单标签主机名。
- **CORS 不能回 `*`**。公开站上回 `*` 等于任何网站都能借访客的浏览器把它当免费代理
  （借 Vercel 的出口 IP 绕过各种 IP 限制）。只对白名单来源回 CORS 头，其他来源直接 403。
  不带 Origin 的请求（curl 等）仍放行 —— 浏览器不会为跨站请求省略 Origin。
- **请求体上限 8MB**，PUT 的 body 直接进内存。

### 改项目名 / 加自定义域名时

必须同步改 `api/webdav.js` 的 `DEFAULT_ORIGINS`（或环境变量 `QZ_ALLOWED_ORIGINS`，
逗号分隔，支持前缀通配）。

> 漏了这一步的表现极具迷惑性：**站点本身照常打开，只有「网盘同步」会 403** ——
> 那是最难联想到域名的一类故障。

### 域名

**当前正式地址：https://resumeself.vercel.app**（Vercel 免费子域，无需维护、不会过期）。

`resumeself.com` / `www.resumeself.com` 曾经绑在项目上，但**该域名从未注册过**，
因此解析结果是 NXDOMAIN，任何人都打不开。Vercel 的项目域名页仍会把它们显示为
`verified: true` —— 那只表示「域名绑定到了本项目」，**不表示域名真实存在**，别被它误导。

> 排查这类问题的正确做法是问权威源，而不是看本地递归解析的结果：
> ```bash
> whois -h whois.verisign-grs.com resumeself.com   # 注册局是否收录：No match = 未注册
> dig resumeself.com @a.gtld-servers.net           # .com 顶级域的委派：NXDOMAIN = 不存在
> ```
> 注意区分两种失败：**NXDOMAIN（域名不存在）** 与 **返回错误的 IP（DNS 污染）**。
> 两者的处理方式完全不同，不要都归因成「网络问题」。

将来若买了自定义域名，在注册商处加：

```
A     <你的域名>            76.76.21.21
A     www.<你的域名>        76.76.21.21
```

或把 nameserver 改为 `ns1.vercel-dns.com` / `ns2.vercel-dns.com`。
配好后**还须同步 `api/webdav.js` 的 `DEFAULT_ORIGINS`**（见上一节），否则网盘同步会 403。

### 随站发布的本地组件：邮件桥

站点的「邮件中心」**必须有一个跑在用户自己电脑上的小服务**：
浏览器不允许网页直连 IMAP/SMTP，也不该把邮箱密码交给任何一个网站。

源码在 `mail-bridge/`，用法见 `mail-bridge/README.md`：

```bash
cd mail-bridge
npm install
cp bridge.config.example.json bridge.config.json   # 填自己的邮箱与授权码
npm start                                          # 首次启动生成 bridge.token 并打印
```

**它是可选的** —— 不装，网站照常使用，只是邮件中心不可用、投递状态要手动改。
默认地址 `http://localhost:8787`。

设计约束（改这个目录前必读）：

- **只监听 `127.0.0.1`**。它持有邮箱凭据，绝不能绑 `0.0.0.0`。
- **除 `/api/health` 外所有端点都要校验 `X-QZ-Token`**，比较用 `crypto.timingSafeEqual`。
- **不依赖任何外部 CLI** —— 上一版靠 `execFile` 调一个特定工具，只有作者本机装了它，
  对公开项目等于没有。
- **中文搜索在本地做**，不用 IMAP `SEARCH`（很多服务器只认 ASCII，中文关键词直接搜不到）。
  代价是每次拉最近 300 封再过滤。
- **发信是两阶段的**：先返回 `{ need_confirm, confirmation_token, summary }`，
  带上 token 再发，防止用户没看清收件人就把邮件发出去。
- `QZ_DEMO=1` 提供演示数据，**这是唯一能自动化验证「网站 ↔ 桥」这段的方式**。

### 质量巡检

零依赖的 CDP 无头浏览器巡检：

```bash
npm run build && npm run preview     # 另开一个终端
node scripts/qa-e2e.mjs views        # 遍历全部板块，抓控制台报错
node scripts/qa-e2e.mjs mobile       # 390×844 窄屏：横向溢出 / 汉堡菜单 / 浮窗
node scripts/qa-e2e.mjs typing       # 弹窗内真实键盘输入（焦点是否被重渲染抢走）
node scripts/qa-e2e.mjs crud         # 各模块「新建 → 刷新 → 仍在」
node scripts/qa-e2e.mjs pwa          # Service Worker + 断网重载
node scripts/qa-e2e.mjs stacklock    # 叠加弹窗后页面是否还能滚动
node scripts/qa-webdav-guard.mjs     # /api/webdav 安全回归
```

> ⚠️ **给巡检脚本加拦截器时的坑**：CDP 的 `Fetch.enable` 是**整组替换** `patterns`，
> 不是追加。任何一个场景调它都会静默关掉别的桩 —— 而桩一关请求就直连真实服务，
> 症状会伪装成产品缺陷（曾让网盘同步报出「网盘上的备份文件为空」，
> 实际是云端桩把 `/api/webdav` 的请求接走、按 Supabase 形状回了）。
> 每个 `Fetch.requestPaused` 处理器**开头必须自己判断 URL**，不属于自己的直接 return。
